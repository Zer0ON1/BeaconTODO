## 1. 产品概述

### 1.1 背景与定位

日常多项目并行时，待办管理有两个高频痛点：

1. **事情拆不细**：一个待办（如"等保整改"）包含十几个执行步骤，缺乏有序的节点结构，整体进度不可见；
2. **关键待办看不到**：正在处理的待办淹没在层层窗口里，希望它能像便签一样钉在屏幕最上面，随时勾选与编辑。

BeaconTODO 用四级结构（**分组 ▸ 待办 ▸ 节点**，关键节点可标记为里程碑）解决"拆解与进度"问题，用**置顶小窗**（Beacon，如灯塔常驻屏幕）解决"常驻速达"问题，并用**日历**与**泳道（状态看板）**两种视图把时间与进度维度可视化。

### 1.2 目标用户

| 用户 | 场景 |
| --- | --- |
| 首要：作者本人（系统集成运维工程师） | 多项目并行、每日结构化记录、周报/月报汇总、等保整改类长周期任务跟踪 |
| 扩展：Windows 重度知识工作者 | 需要"大任务拆解 + 时间可视化 + 桌面常驻"的个人管理用户 |

### 1.3 产品目标

- **G1 结构化**：待办可拆为有序节点，节点可挂里程碑；拖拽调整顺序**只改排序、不动其他属性**。
- **G2 可视化**：日历视图（日粒度）+ 泳道视图（状态看板）双通道呈现。
- **G3 常驻**：任意待办一键置顶为桌面小窗，支持单独置顶与合并置顶两种模式，小窗内可编辑待办、管理节点。
- **G4 本地优先**：零账号、离线可用、启动快、数据可导出导入、可备份。
- **G5 轻量易分发**：安装包小、一键打包、提供便携版。

### 1.4 命名（已定）

**BeaconTODO**（灯塔）：置顶小窗如灯塔常驻屏幕，直指产品差异点；相比 WhatTODO 更具品牌感，缩写 BTD 可用于仓库/包名。
历史备选：泊岸（里程碑=港湾隐喻）/ 潮汐清单（时间节奏）/ WhatTODO（直白）。

## 2. 核心概念与关系

| 概念 | 定义 | 关键属性 |
| --- | --- | --- |
| 分组 Group | 待办的容器，按项目/场景划分 | 名称、颜色、排序、归档 |
| 待办 TODO | 一件需要完成的事 | 优先级、起止日期、状态、进度（由节点推导） |
| 节点 Node | 待办的最小执行单元，**有序** | 序号、起止日期、**是否里程碑（滑块）**、状态 |
| 里程碑 Milestone | 节点的一个标记：该节点是关键检查点 | 由节点自身字段表达（is_milestone），不再独立建实体 |
| 置顶小窗 | 桌面常驻的迷你编辑窗，含 1..N 个待办 | 位置记忆、置顶开关、可多开 |

**关系**：

- 1 分组 ▸ N 待办
- 1 待办 ▸ N 节点
- 1 待办 ▸ 0..N 里程碑节点（**里程碑是节点的一个布尔标记，不是独立实体**）
- 1 置顶小窗 ▸ 1..N 待办（合并模式成员数 > 1；单独模式即成员数为 1 的窗口）

## 3. 功能需求（v0.1）

标记说明：★ = 本版本核心差异点。

### F1 待办分组管理

**用户故事**：作为用户，我希望按项目把待办分组成不同容器，并能快速增删与整理。

| 编号 | 功能点 |
| --- | --- |
| FP1.1 | 新建分组：名称（必填）+ 颜色（8 色预设）；可选 emoji 图标 |
| FP1.2 | 重命名 / 换色 / 归档 / 删除 |
| FP1.3 | 删除分组时提供两种处理：**迁移到其他分组** 或 **连同组内待办一并删除**（强确认） |
| FP1.8 | **（v0.1.5）删除分组弹窗与删除待办同款**：主题化确认框（危险图标 + 分组名 + 组内待办数），提供**三个按钮**——「仅删分组」（待办迁移到默认分组，按钮副标题写明迁移目标与数量）、「删除分组及所有待办」（红色 + 不可撤销标记 + 数量说明）、「取消」；Esc 与点击遮罩均等同取消；空分组时两个选项文案改写为"该分组没有待办"；无其他分组可迁移时「仅删分组」置灰并提示原因 |
| FP1.4 | 归档分组在侧栏隐藏（可在"已归档"入口查看、恢复） |
| FP1.5 | 分组拖拽调整顺序 |
| FP1.6 | 侧栏每组显示：颜色条、待办数量、完成进度（如 3/5） |
| FP1.7 | 默认分组「收件箱」不可删除、不可归档 |

**验收**：分组增删改、归档/恢复、删除时的迁移/级删两条路径均可用且数据一致。

### F2 待办管理

**用户故事**：作为用户，我希望在分组下创建待办，设定优先级与起止日期，并看到整体进度。

| 编号 | 功能点 |
| --- | --- |
| FP2.1 | 字段：标题（必填）、描述、优先级、起止日期、状态 |
| FP2.2 | 状态机：未开始 → 进行中 → 已完成；附加 已阻塞 / 已归档 |
| FP2.3 | 自动规则：节点全部完成 → 待办自动完成（设置项，默认开启）；手动完成待办 → 询问"是否一并完成未完成节点"（记住选择） |
| FP2.4 | 进度 = 已完成节点数 / 总节点数；无节点时显示"—" |
| FP2.5 | 排序：手动（默认）/ 按优先级 / 按截止日期 / 按创建时间 |
| FP2.6 | 已完成待办在列表置底并淡化（设置项） |
| FP2.7 | **（v0.5）新建与编辑共用同一个居中弹窗表单**（标题/备注/分组/优先级/状态/起止日期/节点），不再使用右侧抽屉；Esc 或 ✕ 关闭 |
| FP2.8 | **（v0.5）弹窗内编辑全部为本地草稿，点「保存」一次性提交**；取消不产生脏写。节点支持新增/改标题/勾完成/◆ 里程碑开关/拖拽排序/删除 |
| FP2.9 | **（v0.5）保存校验**：标题非空 + 至少 1 个节点，否则保存按钮置灰并提示 |
| FP2.10 | **（v0.5）删除待办**：弹主题化危险确认框（显示待办名与不可撤销说明）→ 确认后删除；删除**幂等**（重复删除静默成功，不报 "todo not found"）；同时从所有置顶窗口移除该待办，成员清空的置顶窗自动关闭 |
| FP2.11 | **（v0.7）列表卡片点击 = 就地展开节点**（高度动画 + 折叠箭头），展开区可直接勾选完成；进入编辑仍点「编辑」按钮 |

**验收**：状态流转、进度计算、自动完成规则、四种排序均正确；编辑弹窗可正常开关；取消不落库；删除有确认、无残留报错、置顶窗同步清理。

### F3 待办节点管理（含拖拽排序）★

**用户故事**：作为用户，我希望把一个待办拆成多个节点并调整先后顺序，**且调整顺序时绝不会误改节点的里程碑、日期等属性**。

| 编号 | 功能点 |
| --- | --- |
| FP3.1 | 节点字段：标题（必填）、备注、起止日期（可空）、里程碑（可空）、状态、完成时间 |
| FP3.2 | 节点增删改：行内编辑标题；展开行设置里程碑与日期；删除节点（二次确认） |
| FP3.3 | **拖拽排序（核心规则）**，详见下文 |
| FP3.4 | 排序实现：sortOrder 采用间隔整数（步进 1000），落位时仅重算相邻节点，避免全表更新 |

**FP3.3 拖拽排序核心规则**：

1. 在节点编辑器中，按住节点行左侧手柄 ⋮⋮ 上下拖动；
2. **仅改变 sortOrder（顺序）**；该节点的里程碑、起止日期、优先级、标题、备注、完成状态一律不变；
3. 拖动过程中，行内其他属性以"锁定"样式呈现（置灰 + 锁图标），向用户明示"本次操作仅排序"；
4. 目标位置出现插入指示线；松开即落位并即时持久化；
5. 拖拽阈值 5px，避免与点击冲突；单击行 = 选中/进入编辑；
6. 键盘替代：聚焦节点行后 Alt+↑ / Alt+↓ 移动，效果与鼠标拖拽一致；
7. 完成/取消完成、修改日期、切换里程碑等操作**不触发自动重排**——手动顺序是权威顺序；
8. 节点只能在所属待办内排序（v0.1 不支持跨待办移动节点）。

**验收**：

- 拖拽落位后逐字段比对：除顺序外所有属性值不变（含 milestone_id、起止日期、状态）；
- 连续拖拽 10 次无乱序、无重复 sortOrder；
- 重启应用后顺序保持；
- 键盘与鼠标操作结果一致。

### F5 里程碑设定（节点标记制）

**用户故事**：作为用户，希望把某个节点标成里程碑（关键检查点），不用单独维护一套里程碑列表。

> **v0.4 变更**：里程碑从"独立实体 + 节点外键"改为"**节点上的布尔标记**"。节点行内的滑块一开即为里程碑；不再有里程碑列、里程碑下拉框、里程碑增删改界面。

| 编号 | 功能点 |
| --- | --- |
| FP5.1 | 节点行内提供**里程碑滑块**（开关），开启即把该节点标记为里程碑（◆ 图标呈现） |
| FP5.2 | 里程碑节点与非里程碑节点在排序、完成、日期上完全同权，仅多一个视觉标记 |
| FP5.3 | 待办编辑器底部提供「**◆ 新建里程碑**」入口：输入标题直接创建一个 is_milestone = true 的节点 |
| FP5.4 | 里程碑进度沿用节点完成度（已完成节点 / 总节点），编辑器头部显示里程碑数量与完成情况 |
| FP5.5 | 历史数据兼容：旧 `milestones` 表保留但不读不写；旧 `nodes.milestone_id` 置空不再使用 |
| FP5.6 | **（v0.7）完成度旁显示里程碑进度 `◆ 已完成/总数`**（列表卡片与置顶小窗均显示，无里程碑节点时不显示） |

**验收**：滑块开关可正常切换并持久化；里程碑节点在编辑器、日历、置顶窗中显示 ◆；新建里程碑入口可用；旧库升级后数据不丢失。

### F6 起止日期

**用户故事**：作为用户，希望为待办和节点设定计划周期，并在日历上看到它们。

| 编号 | 功能点 |
| --- | --- |
| FP6.1 | 待办与节点均有 start_date / end_date，均可为空 |
| FP6.2 | 校验：结束日期早于开始日期时拒绝保存并提示 |
| FP6.3 | 语义：待办起止日期 = 计划周期；节点日期 = 执行周期；不要求互相包含，超出时编辑器给弱提示 |
| FP6.4 | 逾期判定：end_date < 今天 且 未完成 → 逾期（红色标识；看板中进入"已逾期"列） |

**验收**：日期校验、日历渲染、逾期标识正确。

### F7 日历视图

| 编号 | 功能点 |

### F8 泳道图视图（状态看板）★

**用户故事**：作为用户，希望按待办状态分列总览所有待办，一眼看出谁未开始、谁在进行、谁已逾期、谁已完成，并能在列间拖动更新状态。

## 5. 数据模型

SQLite 单文件存储；所有表带 created_at / updated_at（ISO 8601）。

**groups 分组**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| name | TEXT NOT NULL | 分组名 |
| color | TEXT | 8 色预设之一 |
| icon | TEXT | 可选 emoji |
| sort_order | INTEGER | 手动排序 |
| archived | INTEGER | 0/1 |

**todos 待办**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| group_id | TEXT FK → groups.id | 所属分组 |
| title | TEXT NOT NULL | 标题 |
| description | TEXT | 描述 |
| priority | INTEGER | 0=P0 最紧急 / 1=P1 紧急 / 2=P2 一般 / 3=P3 闲时，默认 2 |

| start_date / end_date | TEXT NULL | 计划周期 |
| sort_order | INTEGER | 手动排序 |
| completed_at | TEXT NULL | 完成时间 |

**nodes 待办节点**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| todo_id | TEXT FK → todos.id | 所属待办（级联删除） |
| title | TEXT NOT NULL | 标题 |
| note | TEXT | 备注 |
| is_milestone | INTEGER (bool) | **是否里程碑（v0.4 新增，滑块控制）** |
| milestone_id | TEXT NULL | 旧字段，v0.4 起退役（恒为 NULL，保留仅为兼容） |
| start_date / end_date | TEXT NULL | 执行周期 |
| status | TEXT | 未开始/进行中/已完成 |
| sort_order | INTEGER | **手动顺序，拖拽只改此字段** |
| completed_at | TEXT NULL | 完成时间 |

**milestones 里程碑（v0.4 起退役）**

> 里程碑改为节点标记后不再读写；表结构保留以免旧库升级报错，导出数据也不再依赖它。

**pin_windows 置顶小窗**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | 窗口 UUID |

| width / height | INTEGER | 窗口尺寸 |
| always_on_top | INTEGER | 1/0 |

**settings 设置**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| key | TEXT PK | 设置项 |
| value | TEXT | JSON 值 |

**索引**：todos(group_id)、nodes(todo_id, sort_order)、nodes(milestone_id)、milestones(todo_id)。

**存储与备份**：数据库文件位于用户数据目录（如 `%APPDATA%/BeaconTODO/beacon.db`），WAL 模式；启动时自动备份到 `backups/`（默认保留最近 **5 份**）；JSON 全量导出/导入（设置页操作，含 groups / todos / nodes / milestones）。

| 维度 | 结论 |
| --- | --- |
| 选型理由 | ① 轻量化：安装包约 5–15MB、常驻内存远低于 Electron；② 易打包构建：`tauri build` 一键产出 NSIS/MSI 安装包与便携 exe；③ Win11 自带 WebView2 运行时，无需额外分发；④ 桌面能力满足全部需求（多 WebviewWindow、alwaysOnTop、无边框、全局快捷键） |

**架构分层**

- 前端（WebView2 渲染）：React 18 + TypeScript + Vite + Zustand（状态管理）+ Tailwind CSS + dnd-kit（节点列表拖拽）+ 自绘泳道看板（DOM/HTML，支持跨列拖拽）+ react-i18next（i18n）
- Rust 后端（src-tauri）：
  - tauri-plugin-sql：SQLite + 可回滚迁移（schema 见 §5）
  - tauri-plugin-store：设置项 KV
  - tauri-plugin-global-shortcut：Ctrl+Shift+P 等全局快捷键
  - tauri-plugin-dialog / tauri-plugin-fs：JSON 导出、备份文件读写
  - tauri-plugin-positioner：托盘与多屏边界处理
  - tauri-plugin-log：结构化日志
- IPC 边界：前端一律经 `invoke` 命令访问数据，命令层做输入校验；前端不直连文件系统
- 命令分层（对齐工程规范）：commands（解析参数）→ services（业务规则/事务）→ repositories（SQL），错误类型化并全局映射

**打包产物**：Windows x64 NSIS 安装包 + 便携版（单 exe）。

**迁移说明**：数据库 schema 与 UI 解耦，未来若需迁移其他外壳，数据层不变。
